请生成前端代码时严格遵守以下规范：

1. 目录与文件结构：
- 针对后端 entity 目录下的所有实体类，在 views 目录下创建对应的功能模块文件夹，文件夹名称使用复数形式（例如：UserEntity 对应 users）。
- 在每个功能模块文件夹内，必须包含一个主页面文件 index.vue。
- 针对后端 entity 目录下的所有实体类，在 api 目录下生成对应的接口定义文件，文件名与实体类名保持一致（例如：UserEntity 对应 user.js）。

2. 视图层 (Views)：
- index.vue 文件必须使用 <script setup> 语法糖。
- index.vue 文件必须使用标准的单文件组件结构，包含 <template>、<script setup> 和 <style scoped> 三个部分。
- index.vue 文件中，必须通过 import 语句引入对应的 API 文件。
- index.vue 文件中，不需要编写任何具体的业务逻辑代码，只需保留基础的模板结构。
- 添加注释时，必须通俗易懂，简单明了，不能使用专业术语，只能使用普通语言。

3. 接口层 (API)：
- api 目录下的接口文件，必须使用 axios 进行请求封装。
- api 目录下的接口文件，必须导出一个对象，对象中包含 list、get、create、update、delete 五个基础方法。
- api 目录下的接口文件，不需要实现具体的请求逻辑，只需定义方法结构。

4. 路由配置 (Vue Router)：
- 针对每个功能模块，必须在 router 目录下配置对应的路由信息。
- 路由路径必须与 views 目录下的文件夹名称保持一致。
- 路由配置中，必须使用懒加载的方式引入页面组件。
- 路由配置中，必须包含 meta 字段，用于定义页面标题等元信息。

5. 状态管理 (Pinia)：
- 针对需要跨组件共享的状态，必须在 store 目录下创建对应的模块。
- 状态模块必须使用 defineStore 函数进行定义。
- 状态模块中，必须包含 state、getters 和 actions 三个部分。
- 状态模块中，不需要编写任何具体的业务逻辑代码，只需定义状态结构和操作方法。

6. 样式与组件规范 (Element Plus)：
- 页面中使用的 UI 组件，必须优先使用 Element Plus 组件库提供的组件。
- 禁止在模板中直接使用原生的 HTML 标签（如 <button>、<table> 等）来实现 UI 功能。
- 样式必须写在 <style scoped> 标签内，避免全局样式污染。
